# Development

Start by checking Git status and remotes, then read `docs/PROJECT_STATE.md` and `docs/ROADMAP.md`. When a remote is available, inspect the active issue, PR, CI, and unresolved review threads before changing branches.

Work on one milestone PR at a time from validated `main`. Link the issue, validate locally, record measured evidence, update the project state, and post material progress. Merge only when required checks and repository approval policy permit it.

Keep experiments isolated and preserve failed runs. Use authoritative RTL file lists and tool reports. Preserve upstream RTL and constraints. Record missing physical views and unverified gates explicitly. Keep generated EDA databases out of Git. Only add a license after the owner approves the choice.
