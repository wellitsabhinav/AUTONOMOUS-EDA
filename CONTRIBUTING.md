# Contributing

Start with the [project state](docs/PROJECT_STATE.md) and follow [AGENTS.md](AGENTS.md). Each milestone needs an issue with explicit acceptance criteria and a feature branch from validated `main`. Open a linked draft PR, post substantive validation evidence, and wait for required checks and applicable approval before merging.

Keep code reviews reproducible. Include the exact commands and environment for each result. See the [experiment protocol](docs/EXPERIMENT_PROTOCOL.md) for physical runs.

For macro and hierarchical submissions, identify the upstream configuration, retain the native view hashes, and state which timing and physical checks the evidence supports. Start with the [OpenTitan readiness guide](docs/OPENTITAN_READINESS.md).

Follow the [documentation design system](docs/DESIGN_SYSTEM.md) for guides, command examples and figures. Run the documentation and provenance checks before opening a PR.
